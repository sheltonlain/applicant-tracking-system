Throwaway prototype

What should the system remember about stage moves?

The question: When staff move an application between stages, should the database keep (A) only the current stage plus a single “closed from” field, (B) a full history of every move (who, when, from, to), or (C) that history plus a required reason when rejecting, withdrawing or reopening? Every button sends the same real-world action to all three options, so you can compare what each one keeps and which everyday questions it can answer.

Stage rules (already decided): forward one stage at a time; back one stage; Reject/Withdraw from any active stage; Reopen sends a Rejected/Withdrawn application back to the stage it was closed from; Hired is permanent.
